# ADR-001 — Monorepo, modular monolith, ports and adapters

Status: **accepted for bootstrap**, 2026-10-26.

## Context
One solo founder with AI coding tools; H0 deadline, limited verified providers, extremely sensitive use cases. Multiple services, queues, blockchain indexing and persisted cases would create unjustified risk.

## Decision
- One repository and one stable \`main\`, short-lived branches per issue.
- \`apps/web\`: Next.js UI with minimal client request wrapper.
- \`services/api\`: FastAPI with \`domain\`, \`application\`, \`adapters\`, \`packs\` boundaries.
- \`packages/contracts\`: versioned JSON Schema for API responses.
- \`evals\`: synthetic reproducible evaluation, not commercial performance claims.
- No database, auth, agent autonomy or external verification in this bootstrap.
- Meta provider port to be implemented only after access/security review, offline deterministic implementation is always labeled.

## Tradeoffs
- No persistent timelines yet; safer privacy defaults but less longitudinal utility.
- Separate Python/TypeScript contract needs tests/codegen in future.
- Frontend and backend may deploy separately; CORS must be explicitly configured.

## Revisit when
Partner tenancy, controlled storage, mobile/Guardian permissions, evidence sources or actual performance measurements require a new ADR.
